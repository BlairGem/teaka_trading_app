## Public interfaces

- `trading_stack.app.create_app(settings=None, runtime=None) -> Flask`: importing the module does not create an app/database. Factory initializes an isolated SQLite memory database, recovered auth and page routes, and paper API routes. Settings may use `sqlite://` or `sqlite:///:memory:` only; inherited DATABASE_URL is ignored. App mode and both live/private flags are forcibly paper/false before runtime/blueprint initialization. No module-level `app` instance remains.
- `LocalCandleProvider(frames: dict[pair, DataFrame], data_origin: str, timeframe='1h')`: copies/validates OHLCV, rejects duplicate timestamps and non-USDT quote pairs. Naive timestamps mean UTC; aware timestamps normalize to naive UTC. Initial clock is unset and exposes no data. `advance(when)` is monotonic. `get_latest_prices(pairs, as_of=None)` caps at both its clock and supplied bound. `get_historical_data(pair, timeframe, *, start_date=None, end_date=None, limit=100)` likewise caps at the clock.
- `PaperRuntime(provider, config: PaperConfig | None=None)`: one broker/account per ORM user, one shared dataset/clock per runtime. `account(user_id)`, `balance(user_id)`, `positions(user_id)`, `manual_order(user_id, pair, side, quantity)`, `close(user_id, position_id, price=None, reason='manual_close')`, `replay(user_id, start, end)`. Positions carry stable ORM execution IDs and strategy ownership; a strategy cannot close another strategy's lot. Manual SELL addresses only manually owned exposure; explicit owned-position close can close a strategy lot.
- `run_trading_engine(runtime=None, user_id=None, candle_time=None)`: finite one-candle call. Omitted runtime resolves the current app's `paper_runtime` extension. User and candle time are required. Stable strategy-ID order, per-user/strategy/pair/candle deduplication plus processed-candle guard. Signals use only prior completed history, fill at current open, then stops/takes apply, then close marking. No short opening. A gap through a stop fills at the worse open; a candle touching both thresholds uses stop first.
- `execute_trade_from_signal(signal, position_size, runtime=None, user_id=None)`: requires explicit owner and pending signal, uses the actual requested quantity, and never dispatches live. Public `get_active_positions`, `get_position_details`, `close_position`, and `update_orders_status` use paper state; orders are synchronous.
- `PaperBroker(config, log_path=None, clock=None)`: backward-compatible optional clock collaborator. Runtime injects simulated ISO time directly; fill timestamps are never rewritten after recording. Economic/event-time deterministic comparisons exclude only generated order IDs.
- `paper_replay.replay_csv(runtime, user_id, csv_path, pair, timeframe, start, end, data_origin, output_path)`: finite load/run/export, CSV requires exactly timestamp/open/high/low/close/volume, at most 20 MB/100000 rows, nonempty origin, new `.json` target. Source path and SHA256 are exported. Existing files are refused. Failed reserved outputs are preserved rather than deleted.

`GET /api/paper/runs` returns the current user's ORM run records. `POST /api/paper/replay` accepts `csv_path`, `trading_pair`, `timeframe`, `start`, `end`, `data_origin`. ## Explicit limits and self-review

- Memory ORM/account state intentionally lasts only for the app process. No persistence, recovery/resumption, schedulers, providers, real account connection, or multiworker architecture was added. A single loopback process is the startup contract.
- Accounting is USDT only; default broker allowed symbols are BTC-USDT/ETH-USDT/SOL-USDT. A configured allowed-symbol list may extend this to supported USDT pairs. No FX conversion or mixed-currency aggregation is implied.
- One runtime owns one dataset/clock. Reading balances can initialize accounts without preventing first CSV load. After economic activity, changing CSV identity/hash/pair/timeframe/origin is refused. Same caller/same CSV/range returns its cached run without duplicating fills; each requested export still requires a new output filename. A later other-user replay of an earlier range is rejected before changing accounts/clock. An independent historical replay or different dataset requires a fresh runtime/app. No user's request can rewind or replace data under another user's economic state through the web/CSV entry.
- Engine economics are deterministic floating-point simulations. Entry/exit rules use completed bars and next opens, protection applies intrabar, and final liquidation uses final close. Fees/slippage are explicit. Wall-clock ORM creation metadata and generated record IDs are not strategy inputs.
- ML artifacts, TA-Lib-only/custom MATLAB indicators, MATLAB, futures, messaging and provider managers remain inactive. Existing inactive legacy source is retained behind separate functions; the new factory registers only paper handlers and public engine functions choose paper state.
- Reviewed checks: factory before DB initialization; no inherited persistent URI; no manager import in guarded inherited-live runs; actual manual quantity/risk context; normalized nested equity in the real loop; user/strategy lot ownership; replay clock/filtering; held close bypass; complete finite export; all 90 tests and final diff whitespace check.
